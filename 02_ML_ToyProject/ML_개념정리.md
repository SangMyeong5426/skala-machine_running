## 0. 한 장 요약

> **기계학습 = 데이터에서 규칙을 사람이 아니라 기계가 찾게 하는 것**

| 구분 | 정답(라벨)이 | 하는 일 | 예 |
| --- | --- | --- | --- |
| **지도학습** | **있다** | 정답을 맞히도록 학습 | 집값 예측, 스팸 분류 |
| **비지도학습** | **없다** | 비슷한 것끼리 묶거나 압축 | 고객 세분화, 차원 축소 |
| 강화학습 | 보상만 있다 | 시행착오로 최적 행동 학습 | 게임, 로봇 제어 |

**지도학습은 다시 두 갈래다.**

| | 예측하는 것 | 예 | 성능 지표 |
| --- | --- | --- | --- |
| **회귀 (Regression)** | **숫자** | 가격, 온도, 수요량 | MAE, RMSE, R² |
| **분류 (Classification)** | **범주** | 합격/불합격, 스팸 여부 | Accuracy, Precision, Recall, F1, AUC |

> 이 구분이 중요한 이유: **지표가 완전히 다르다.** 회귀 모델에 Accuracy 를 쓸 수 없고,
> 분류 모델에 RMSE 를 쓸 수 없다.

## 1. 지도학습 — 회귀

### 선형 회귀 (Linear Regression)
데이터를 가장 잘 지나는 **직선(또는 평면)** 을 찾는 것.
`y = w₁x₁ + w₂x₂ + ... + b` — 여기서 **w 를 찾는 것이 학습**이다.

- **장점** 해석이 쉽다. *"광고비가 1 늘면 매출이 w 만큼 는다"* 라고 말할 수 있다
- **단점** 관계가 직선이 아니면 못 맞춘다

### 정규화(규제)가 붙은 회귀

| | 하는 일 |
| --- | --- |
| **Ridge (L2)** | 가중치가 너무 커지지 않게 억제 |
| **Lasso (L1)** | 억제하다가 **일부 가중치를 0으로** 만듦 → 자동 변수 선택 |

> **실습1(XGBoost)의 `reg_lambda` 와 같은 개념이다.** 용량을 억제하는 '제동' 손잡이.

## 2. 지도학습 — 분류

| 알고리즘 | 한 줄 | 이미 해본 것 |
| --- | --- | --- |
| **Logistic Regression** | 직선을 긋고 **확률(0~1)** 로 변환해 분류 | ANN 출력층의 Sigmoid 와 같은 함수 |
| **KNN** | 가장 가까운 k개 이웃의 **다수결** | **실습2** |
| **Decision Tree** | 질문을 반복해 데이터를 쪼갬 (스무고개) | 실습1의 기반 |
| **Random Forest** | 트리 여러 개를 만들어 **투표** | 실습1 XGBoost 와 사촌 |
| **SVM** | 두 집단 사이 **간격(margin)이 가장 넓은** 경계를 찾음 | — |

### Decision Tree 와 Random Forest 의 차이

- **Tree 1개**: 데이터를 조금만 바꿔도 구조가 확 바뀐다 (불안정)
- **Random Forest**: 데이터·변수를 **조각내어** 트리 여러 개를 만들고 투표
  → 트리들이 **서로 다른 실수**를 해서 합칠 때 상쇄된다

> **실습1에서 확인한 것과 같다.** `subsample`·`colsample_bytree` 를 낮추면
> 트리마다 다른 데이터를 봐서 오차가 상쇄됐다. Random Forest 는 그걸 기본으로 하는 모델이다.

### SVM 의 핵심 — Margin
두 집단을 가르는 선은 무수히 많다. SVM 은 그중 **양쪽 끝 데이터와의 간격이 가장 넓은** 선을 고른다.
경계에 가장 가까운 데이터를 **서포트 벡터**라 하고, 그 점들만 경계를 결정한다.
직선으로 못 가르면 **커널(kernel)** 로 차원을 올려서 가른다.

## 3. 비지도학습

### 군집화 (Clustering) — **실습3에서 전부 다룸**

| 방법 | 어떻게 묶나 | 특징 |
| --- | --- | --- |
| **K-Means** | 중심점 k개 찍고 → 가까운 쪽 배정 → 중심 재계산, 반복 | k 를 사람이 정해야 함. 동그란 덩어리에 강함 |
| **Hierarchical** | 가까운 것부터 하나씩 합쳐 올라감 (덴드로그램) | k 를 나중에 정할 수 있음 |
| **DBSCAN** | 빽빽한 곳만 군집으로 인정, 나머지는 **노이즈** | k 불필요. 모양이 자유로움. **밀도 차이가 없으면 실패** |

> **실습3의 결론을 그대로 가져올 수 있다** — 초승달(Moon) 데이터에서는 DBSCAN 만 정답이었지만,
> 실제 고객 데이터에서는 어떤 설정으로도 군집을 1개밖에 못 만들었다.
> **데이터 형태가 방법을 정한다.**

### 차원 축소 — PCA
변수가 많으면 **서로 겹치는 정보**가 많다. PCA 는 정보 손실을 최소화하며 축을 줄인다.

- **왜 필요한가** 시각화(2D), 계산 속도, 중복 제거
- **주의** 새로 만들어진 축(주성분)은 **원래 변수의 혼합**이라 해석이 어렵다

> 실습2에서 확인 — `SelectKBest` 로 뽑은 상위 10개 변수는 서로 상관 0.99 라
> **정보가 사실상 2차원**이었다. PCA 5개가 30개 변수에 근접한 이유가 이것이다.

## 4. 모델 성능평가 ★ 가장 중요한 파트

### 4-1. 회귀 지표 (그림 `mlt_fig2_regression_metrics.png`)

| 지표 | 계산 | 성질 |
| --- | --- | --- |
| **MAE** | 오차 절댓값의 평균 | 이상치에 **둔감**. 단위가 원래 값과 같아 해석 쉬움 |
| **MSE** | 오차를 **제곱**해 평균 | 이상치에 **매우 민감**. 단위가 제곱이라 해석 어려움 |
| **RMSE** | MSE 에 루트 | 민감하지만 **단위가 원래대로** 돌아옴 |
| **R²** | 분산을 얼마나 설명했나 (0~1) | 1에 가까울수록 좋음. 음수도 가능 |

**같은 데이터에 이상치 1개만 섞으면:**

| | MAE | RMSE | MSE |
| --- | ---: | ---: | ---: |
| 오차가 고르게 작을 때 | 0.96 | 1.15 | 1.3 |
| **이상치 1개 추가** | **1.90** (2배) | **4.61** (4배) | **21.3** (16배) |

→ **큰 실수를 특별히 싫어해야 하면 RMSE, 모든 오차를 동등하게 보려면 MAE.**

> 실습1에서 겪은 것 — MAE 는 좋아졌는데 R² 는 나빠지는 모델이 있었다.
> *"평균적으로는 더 정확하지만 가끔 크게 헛짚는"* 모델이었다. **지표 하나만 보면 판단이 뒤집힌다.**

### 4-2. 분류 지표 (그림 `mlt_fig1_confusion.png`)

모든 분류 지표는 **혼동행렬** 하나에서 나온다.

|  | 예측: 아니다 | 예측: 맞다 |
| --- | --- | --- |
| **실제: 아니다** | TN (맞게 넘김) | **FP — 헛짚음** |
| **실제: 맞다** | **FN — 놓침** | TP (맞게 잡음) |

| 지표 | 계산 | 의미 |
| --- | --- | --- |
| **Accuracy** | (TN+TP) / 전체 | 전체 중 맞힌 비율 |
| **Precision** | TP / (TP+FP) | **"맞다"고 한 것 중 진짜** — 헛짚음이 적은가 |
| **Recall** | TP / (TP+FN) | **진짜 중에 잡아낸 비율** — 놓친 게 적은가 |
| **F1** | 위 둘의 조화평균 | 둘의 균형 |

**Precision 과 Recall 은 맞바꾸는 관계다.** 기준을 느슨하게 하면 많이 잡지만(Recall↑) 헛짚음도 는다(Precision↓).

| 상황 | 무엇을 중시 |
| --- | --- |
| 암 진단, 사기 탐지 | **Recall** — 놓치면 치명적 |
| 스팸 필터 | **Precision** — 정상 메일을 스팸함에 넣으면 안 됨 |

### 4-3. ⚠️ Accuracy 의 함정 — 실습4에서 직접 겪은 것

**클래스가 불균형하면 Accuracy 는 지표 구실을 못 한다.**

Bank Marketing 데이터(가입률 11.7%)에서:

| 모델 | Accuracy | AUC |
| --- | ---: | ---: |
| **전부 '미가입' 으로 찍기** | **0.8830** | 0.5000 |
| 로지스틱 회귀 | 0.8934 | 0.7712 |
| ANN (최종) | 0.8938 | 0.7913 |

**Accuracy 는 셋 다 0.88~0.89 로 붙어 있는데 AUC 는 0.50 → 0.79 로 완전히 갈린다.**
아무것도 안 하는 모델과 구별조차 안 된다.

> **먼저 "전부 다수 클래스로 찍으면 몇 %인가"를 계산해 보라.** 그게 진짜 기준선이다.

### 4-4. ROC-AUC
임계값을 0부터 1까지 움직이며 **(놓친 비율, 헛짚은 비율)** 을 그린 곡선의 아래 면적.

- **0.5 = 찍는 것과 같음**, 1.0 = 완벽
- **임계값과 무관**하게 모델의 순위 매기는 능력을 잰다 → 불균형 데이터에 적합

### 4-5. 과적합 / 과소적합과 교차검증

| | Train 성능 | Val 성능 | 진단 |
| --- | --- | --- | --- |
| **과소적합** | 나쁨 | 나쁨 | 모델이 너무 단순 |
| **적정** | 좋음 | 좋음 | — |
| **과적합** | **매우 좋음** | 나쁨 | Train 을 외워버림 |

**교차검증(K-Fold)** — 데이터를 K등분해 번갈아 검증셋으로 쓰고 평균. 한 번의 우연한 분할에 속지 않는다.

> **실습1~4에서 반복 확인한 것**
> - Train 성능은 모델 선택의 근거가 못 된다 (KNN k=1 은 Train 정확도가 자동으로 1.0)
> - **Gap(Train−Val)은 진단 지표이지 최소화 대상이 아니다** — Gap 이 가장 작은 모델이 가장 나빴다
> - 차이가 **분할마다 흔들리는 폭보다 큰지** 먼저 봐야 한다

## 5. Toy Project 대비 — 순서와 체크리스트

```
1. 문제 정의    회귀인가 분류인가 → 지표가 정해진다
2. 데이터 확인  결측치 / 분포 왜곡 / 클래스 불균형 / 변수 간 중복
3. 전처리      스케일링, 로그변환, 범주형 인코딩
4. 분할        Train / Validation / Test  (Test 는 마지막 1회)
5. 모델 학습    여러 후보 비교
6. 평가        지표 + 그 지표가 무엇을 가정하는지 확인
7. 해석        결과가 업무적으로 말이 되는가
```

**앞선 4번의 실습에서 반복해서 확인된 것들 — 이번에도 그대로 적용된다**

| 교훈 | 어디서 |
| --- | --- |
| **평가 지표를 가장 먼저 정한다** — 불균형이면 Accuracy 는 쓸 수 없다 | 실습4 |
| **전처리가 모델 선택보다 결과를 좌우한다** | 실습2(스케일링) · 실습3(로그변환) |
| **지표 최대화는 목적이 아니다** | 실습3 (Silhouette 1위가 [437,1,1,1]) |
| **차이가 노이즈보다 큰지 본다** — 표준편차를 옆에 놓고 읽는다 | 실습2 |
| **점수를 비교하려면 같은 조건에서 잰 것이어야 한다** | 실습3 조별토의 |
| **Test 는 마지막에 한 번만 연다** | 실습2·3·4 |

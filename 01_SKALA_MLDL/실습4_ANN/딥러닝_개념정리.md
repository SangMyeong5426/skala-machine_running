## 1. 왜 딥러닝인가 — Feature 를 누가 만드나 (p.4~5)

| | Traditional ML (실습1~3) | Deep Learning |
| --- | --- | --- |
| Feature | **사람이** 도메인 지식으로 설계 | **모델이 Layer 마다 스스로** 학습 |
| 예 (신용위험) | 부채비율·연체횟수를 사람이 계산해서 넣음 | Layer1 단순특징 → Layer2 조합 → Layer3 추상적 표현 |
| 성능을 좌우 | **Feature 품질** | **데이터 양 + 구조** |

> 실습2 에서 "스케일링이 성능을 만들었다", 실습3 에서 "로그변환이 만들었다" 고 했던 것 —
> 그게 바로 **사람이 하는 Feature 작업**이다. 딥러닝은 이 부분을 모델 안으로 가져온다.

## 2. Perceptron — 가장 작은 계산 단위 (p.7~10)

뇌의 뉴런을 흉내 낸 것. **입력 → 가중합 → 활성화 → 출력** 이 전부다.

```
z = w₁x₁ + w₂x₂ + ... + b        ← 가중합 (weighted sum)
y = f(z)                          ← 활성화 함수 통과
```

| 부품 | 뜻 | 비유 |
| --- | --- | --- |
| **x** (입력) | 데이터 | 들어오는 신호 |
| **w** (가중치) | 그 입력을 얼마나 중요하게 볼지 | **볼륨 손잡이** |
| **b** (bias) | 전체적으로 얼마나 쉽게 반응할지 | **민감도 조절** |
| **f** (활성화 함수) | 최종 출력으로 변환 | 스위치 |

**학습이란 = w 와 b 를 찾는 것.** (p.40) 활성화 함수는 사람이 미리 정하며 학습 대상이 아니다.

> 교재 p.10: 원래는 *"임계값 θ 를 넘으면 1"* 이었는데, `b = −θ` 로 놓아
> **`Σwx + b ≥ 0`** 형태로 정리한 것이 지금의 bias 다.

## 3. XOR 문제 — 딥러닝이 태어난 이유 ★ (p.12~17)

**Perceptron 하나 = 직선 하나.** 그래서 직선 하나로 나뉘는 문제만 풀 수 있다.
(그림 `dl_fig1_xor.png`)

| 문제 | 규칙 | 직선 하나로? |
| --- | --- | --- |
| AND | 둘 다 1일 때만 1 | ✅ 가능 |
| OR | 하나라도 1이면 1 | ✅ 가능 |
| **XOR** | **서로 다를 때만 1** | ❌ **불가능** |

XOR 은 대각선끼리 같은 답이라 어떤 직선을 그어도 못 가른다.

**해결: 층을 하나 더 쌓는다 (Hidden Layer).**
직선 여러 개를 조합하면 꺾인 경계를 만들 수 있다 → 이것이 **MLP(Multi-Layer Perceptron)**.

> 교재 p.17: *"각각은 선형이지만 전체는 비선형"*
> p.18: 층이 늘수록 표현할 수 있는 경계가 복잡해진다 (직선 → 볼록다각형 → 임의 모양)

## 4. 학습이란 무엇인가 (p.38~45)

```
Predict  →  Measure Error  →  Adjust  →  Repeat
```

**Loss(손실함수)** = 예측이 얼마나 틀렸는지를 숫자 하나로. 회귀는 보통 MSE.

```
L = ½(y − ŷ)²          예: 정답 1.0, 예측 0.7  →  L = 0.045
```

그런데 **Loss 를 아는 것만으로는 부족하다.** (p.45)
*"어떤 가중치를 얼마나 바꿔야 Loss 가 줄어드는가"* 를 알아야 한다. → **기울기(gradient)**

---

## 5. 미분이 필요한 이유 — 딱 한 가지 (p.23~31, 48~51)

미분이 나와서 어려워 보이지만 목적은 하나다.

> **"이 가중치를 조금 바꾸면 오차가 얼마나 변하나?"**

기울기 하나가 **두 가지**를 알려준다.

| 기울기의 | 알려주는 것 | 교재 |
| --- | --- | --- |
| **부호** | 어느 **방향**으로 움직여야 하나 (부호의 **반대** 방향) | p.49 |
| **크기** | **얼마나** 많이 움직여야 하나 | p.50 |

예: `y = x²` 에서 x=2 일 때 기울기 = 4 (양수) → **x 를 줄여야** y 가 작아진다.

### 알아둘 용어

| 용어 | 뜻 |
| --- | --- |
| 평균 변화율 | 두 점을 이은 직선의 기울기 (구간 평균 속도) |
| **미분계수** | 한 점에서의 접선 기울기 (순간 속도). = gradient |
| 도함수 | 미분계수를 x 의 식으로 일반화한 것. `f(x)=x² → f'(x)=2x` |

## 6. Gradient Descent 와 Learning Rate (p.51~54)

기울기 방향으로 내려가되, **그대로 가면 튕겨 나간다.** (그림 `dl_fig2_gd.png`)

```
새 가중치 = 현재 가중치 − (학습률 × 기울기)
     W  ←  W  −  η · ∂E/∂W
```

| Learning Rate | 결과 |
| --- | --- |
| **너무 작다** | 촘촘하지만 **학습이 한없이 느리다** |
| **적당하다** | 잘 수렴 |
| **너무 크다** | 골짜기를 뛰어넘어 **발산(over-shooting)** |

> **실습1 XGBoost 의 `learning_rate` 와 같은 개념이다.** 거기서는 "각 트리의 발언권",
> 여기서는 "한 걸음의 보폭". 둘 다 *"한 번에 얼마나 반영할까"* 를 정한다.

### Optimizer (p.56~57)
학습률을 **자동으로 조절**해주는 알고리즘들. 실무 기본값은 **Adam**.

| | 아이디어 |
| --- | --- |
| SGD | 기본 경사하강 |
| Momentum | 관성을 줘서 작은 웅덩이(Local minimum)를 지나치게 |
| RMSProp | 상황 봐가며 보폭 조절 |
| **Adam** | **Momentum + RMSProp** — 방향도 보폭도 알아서 |

## 7. 역전파 (Backpropagation) 와 Chain Rule (p.34~35, 43)

층이 여러 개면 *"이 오차가 3층 전 가중치 탓인지"* 를 어떻게 아나?

**Chain rule:** 전체 변화율 = 각 단계 변화율의 **곱**

```
dy/dx = (dy/dz) × (dz/dx)
```

예 (p.35): `x=2 → z=x²=4 → y=3z=12`
```
dz/dx = 2x = 4,   dy/dz = 3   →   dy/dx = 3 × 4 = 12
```

**역전파 = 출력 쪽 오차를 Chain rule 로 입력 쪽까지 거꾸로 곱해 내려보내는 것.**
각 층은 *"내 입출력에 대한 미분"* 만 하면 되므로 계산이 단순해진다.

```
① Propagation  : 앞으로 계산해서 예측값을 냄
② 오차 계산     : 예측 vs 정답
③ Backpropagation : 뒤에서부터 각 가중치의 책임(기울기)을 계산 → 수정
```

## 8. 깊어지면 생기는 문제와 대책 (p.65~70)

### Gradient Vanishing / Exploding

| | Vanishing | Exploding |
| --- | --- | --- |
| 현상 | 뒤로 갈수록 기울기가 **0에 수렴** | 기울기가 **폭발** |
| 결과 | 앞쪽 층이 **학습되지 않음** | 발산 |
| 원인 | **Sigmoid/Tanh** 를 여러 번 곱함 | 망이 너무 깊거나 초기화 불량 |
| 대책 | **ReLU**, Batch Normalization | Gradient Clipping |

### 활성화 함수 (p.67)

| | 출력 범위 | 특징 | 주 용도 |
| --- | --- | --- | --- |
| **Sigmoid** | (0, 1) | 확률처럼 해석 가능 / **Vanishing 발생** | 이진 분류 **출력층** |
| **Tanh** | (−1, 1) | 0 중심이라 Sigmoid 보다 나음 | RNN, LSTM |
| **ReLU** | (0, ∞) | `max(0,x)`. 간단하고 Vanishing 적음 | **은닉층 기본값** |

### 과적합 대책

| 기법 | 하는 일 | 주의 |
| --- | --- | --- |
| **Dropout** (p.68) | 학습 때 뉴런을 **무작위로 꺼서** 골고루 학습시킴 | **테스트 때는 끄지 않는다** |
| **Batch Normalization** (p.69) | 층마다 입력 분포를 일정하게 맞춤 | 학습 속도·안정성 향상 |
| **Early Stopping** (p.60) | Validation 오차가 더 안 줄면 중단 | Validation set 필요 |

## 9. Batch / Epoch (p.55)

| 용어 | 뜻 |
| --- | --- |
| **Batch** | 한 번에 몇 개 데이터를 보고 가중치를 고칠 것인가 |
| **Mini Batch** | 전체를 작은 묶음으로 쪼개서 학습 (**실무 표준**) |
| **Epoch** | 전체 학습 데이터를 **한 번 다 본 것** |

예: 데이터 1,000개, Batch Size 100 → 한 Epoch 에 **10번** 가중치 수정
→ 20 Epoch 이면 총 **200번** 수정

## 10. 실습에서 만지게 될 손잡이 (p.61~62)

실습1 XGBoost 를 정리했던 **① 용량 / ② 제동 / ③ 다양성** 틀을 그대로 적용하면:

| 범주 | 딥러닝 손잡이 | 비고 |
| --- | --- | --- |
| **① 용량** | `hidden layer 수`, `층당 node 수` | 많을수록 복잡한 패턴 표현 |
| **② 제동** | `learning_rate`, `epochs`, **Early Stopping**, `weight decay` | 과하게 학습하지 않도록 |
| **③ 다양성** | **Dropout**, `batch_size` | XGBoost 의 subsample 과 같은 역할 |
| **구조 선택** | `activation`(ReLU/Sigmoid), `optimizer`(Adam), **Batch Norm** | 복잡도 축이 아닌 다른 축 |

> 교재 p.62 Cons: *"모델러가 직관적으로 값을 정해야 할 파라미터가 많음 —
> 은닉층 개수, 노드 수, 활성 함수, 학습률, 모멘텀률…"*
> **실습1 XGBoost 튜닝과 같은 구조다.**

### 딥러닝의 Pros and Cons (p.62)

| Pros | Cons |
| --- | --- |
| 비선형 패턴 학습, 높은 정확도 | **많은 데이터 필요** |
| 학습 결과 재활용(전이학습) | **과적합 위험 매우 높음** |
| | 정해야 할 파라미터가 많음 |
| | 컴퓨팅 자원 많이 필요 |

> p.59: *"데이터가 충분하지 않으면 딥러닝 활용은 지양할 것을 권고.
> 사용하더라도 모델 구조를 최대한 단순하게"*
> → 실습 데이터가 작다면 **층을 얕게** 가는 것이 정답일 수 있다.

## 11. 실습 때 확인할 것 (미리 세워두는 관점)

앞의 세 실습에서 반복된 교훈을 그대로 적용한다.

1. **Train 성능은 근거가 못 된다** (실습1) → 딥러닝은 특히 잘 외운다. Validation 곡선을 봐야 한다
2. **차이가 노이즈보다 큰지 봐라** (실습2) → 신경망은 **초기값이 랜덤**이라 seed 마다 결과가 흔들린다.
   같은 설정을 여러 seed 로 돌려봐야 진짜 차이인지 안다
3. **지표 최대화가 목적이 아니다** (실습3) → 무엇을 위해 만든 모델인지 먼저
4. **전처리가 성능을 만들었다** (실습2·3) → 신경망도 **입력 표준화가 사실상 필수**
